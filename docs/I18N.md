# Languages (English and French)

The whole site exists in English and French: every page, every message of the API, every label
shared through `portfolio-common`. This page says how the language of a request is chosen, where
texts live, and the rules a new text must follow.

## How the language is chosen

For each page request (`client/src/hooks.server.ts`), in this order:

1. what the URL asks for: `?lang=fr` or `?lang=en`. It also becomes the visitor's choice, saved for
   a year in the `lang` cookie, except when they had already chosen and the link comes from
   elsewhere (a shared address, a search result: `Sec-Fetch-Site`): the page is then rendered in
   the language asked, and their choice stays. Only a page load saves it: SvelteKit's data
   requests (`__data.json`, which carry the page's `?lang=` after `invalidateAll`) are answered in
   that language but never change the cookie;
2. the `lang` cookie;
3. what the browser prefers (`Accept-Language`);
4. English.

The language switch (`client/src/lib/i18n/LanguageSwitch.svelte`, one per page, next to the
light/dark switch) is a plain link to the current page with `?lang=`: the page is loaded again from
the server. A page never changes language while it lives, so nothing has to be reactive.

Each language of a page has its own address for search engines: English is the address alone,
French adds `?lang=fr` (`localeAlternate` of `client/src/lib/i18n/urls.ts`). A page that search
engines list declares both with a canonical link and `hreflang` alternates: `LocaleLinks.svelte`
does it for the recruiter landing (mounted by the `(app)` layout); the landing
page and the legal pages write their own, next to their share tags. A portfolio is not listed
(`client/src/lib/robots.ts`, CLAUDE.md "Search engines"): it has no canonical or `hreflang` link.
Its experiences page and its page for recruiters keep the preview a shared link gets
(`OpenGraph.svelte`, CLAUDE.md "Link previews"): `og:url` is the address of the language shown,
`og:locale` names it (`en_GB`, `fr_FR`), and the picture is the one drawn in that language
(`og-portfolio-fr.png`, `og-hire-fr.png` in French), from `client/src/services/linkPreview.messages.ts`.

The server writes the language on `<html lang>`; the browser reads it there
(`client/src/hooks.client.ts`). The client sends it to the API as `Accept-Language`
(`client/src/services/portfolio.ts`), and the API keeps it for the request
(`server/services/locale.ts`).

The language in use is **ambient**: `getLocale()` of `portfolio-common` gives it anywhere, in the
three workspaces. Both servers keep it per request with `AsyncLocalStorage`; without a request
(unit tests, scripts, module load) it is English.

## Where texts live

Every text a person can read is a **message**, declared with `defineMessages()` in a
`*.messages.ts` file next to the code that shows it:

| Code | Its messages |
| --- | --- |
| `Foo.svelte` | `Foo.messages.ts` |
| `+page.svelte`, `+layout.svelte`, `+error.svelte` | `page.messages.ts`, `layout.messages.ts`, `error.messages.ts` in the same folder |
| `services/foo.ts`, `common/models/foo.ts`, `server/services/foo.ts` | `foo.messages.ts` |

Several small components of one folder may share one file. Words used everywhere (Save, Cancel,
Try again, Sign in with Google...) are in `client/src/lib/i18n/common.messages.ts`.

```ts
// Foo.messages.ts
import { defineMessages, plural } from 'portfolio-common';

export const m = defineMessages({
	title: { en: 'Your jobs', fr: 'Vos offres' },
	status: {
		draft: { en: 'Draft', fr: 'Brouillon' },
		open: { en: 'Open', fr: 'Ouverte' }
	},
	openings: {
		en: (count: number) => `${count} ${plural(count, 'position', 'positions')}`,
		fr: (count: number) => `${count} ${plural(count, 'poste', 'postes')}`
	},
	details: {
		en: 'Details in the <privacy>privacy policy</privacy>.',
		fr: 'Détails dans la <privacy>politique de confidentialité</privacy>.'
	}
});
```

```svelte
<script lang="ts">
	import { m } from './Foo.messages.ts';
</script>

<h2>{m.title}</h2>
<p>{m.status[job.status]}</p>
<p>{m.openings(count)}</p>
```

A message is `{ en, fr }`: two strings, two functions (a text with values in it), or two arrays.
Reading it (`m.title`) gives the entry of the language in use. TypeScript refuses a message
without its French, and `i18n.test.ts` (client and server) checks every `*.messages.ts` file.

## Rules

1. **Everything a person reads is a message**: visible text, `aria-label`, `title`, `alt`,
   `placeholder`, `<title>` and meta tags, toasts, validation and error messages, dialogs, the
   text of an invitation. Not messages: what people wrote (experiences, job descriptions, notes,
   a portfolio's title, and the address name that heads a portfolio without one),
   names (Portfolio, Google, Claude, Anthropic, GitHub), log lines, texts that code compares
   (an API body the client matches, a `data-` attribute, a test id), and what is sent to a model.
2. **Read a message when it is shown, never at module load.** A module-level
   `const LABELS = { draft: m.draft }` is read once, in English, for every visitor. Use the
   messages object itself (`m.status[key]`), a function (`const tabs = () => [...]`) or a getter.
   Inside a component's instance `<script>` and its markup, reading is fine: that code runs for a
   request.
3. **Whole sentences.** Never glue fragments (`'Delete ' + name + '?'`): word order differs.
   A text with values is a function; the two languages may use the values differently.
4. **Plurals** go through `plural(count, one, other)`: English says "0 projects", French
   "0 projet".
5. **Dates and numbers** are formatted with `intlLocale()` as the locale: `fr-FR` in French, and in
   English the tag the code used before (`intlLocale('en-US')`, `intlLocale(undefined)`), so English
   output does not change. No module-level `Intl.DateTimeFormat`: build it when formatting (cache
   per language if it matters).
6. **A sentence with a link or an emphasis in it** stays one message, with the passage marked up:
   `'Read the <terms>terms of use</terms>.'`, rendered with `Rich.svelte`, which takes a snippet
   per tag. Tags are plain names, do not nest, and must be the same in both languages.
7. **English is the reference.** Moving a text into a message does not change it: the e2e and unit
   tests read the English page. A copy change is a change of its own.
8. **In the API, an error takes a function that reads its message**:
   `new BadRequestError(() => m.invalidDate)` (`server/errors.ts`). The answer is in the visitor's
   language, and the error keeps the English text, which is what the log line says. A body the
   client matches instead of showing is not a message: it is an English constant of
   `server/protocol.ts`, next to the name of the client code that matches it.
9. **A value inside a sentence that needs its own markup** (a name in bold, an address) is an
   empty tag where the value goes: `'Booking <date></date>'`. The snippet renders the value; what
   a person typed never goes through the tag parser.
10. **The legal texts** (`client/src/lib/components/legal/content/`) stay one component per document
   and language: they are documents, not messages.

## Portfolio is a name

The site is called **Portfolio**: a brand, written with a capital, without an article, and never
translated. "On Portfolio, a skill is not a keyword", « Sur Portfolio, une compétence n'est pas un
mot-clé », "Portfolio is free", « Déjà sur Portfolio ? ».

The common noun is kept for one person's page, with a possessive or a demonstrative: "your
portfolio", "their portfolio", "a candidate's portfolio", "this portfolio" (« votre portfolio »,
« le portfolio d'un candidat »). Do not write "a portfolio", "portfolios" or « un portfolio » for
the product or for its pages in general: say Portfolio, "your portfolio", or name the people ("the
candidates you meet", "a candidate's page for recruiters", "One address per account"). Compounds stay ("Portfolio
name", "an example"). The legal texts, which define their own terms, are not covered.

## Writing the French

- "Vous", never "tu". Buttons and menu items are infinitives ("Enregistrer", "Supprimer le
  compte"), sentence case, no capital on every word ("Mes offres d'emploi").
- Straight apostrophes (`'`), `…` for an ellipsis, a plain space before `:`, `;`, `?` and `!`,
  and « guillemets » for quotations: what the French legal pages already do. Type plain spaces:
  `defineMessages()` makes them unbreakable when a French message is read, so a line never starts
  with the sign.
- Generic masculine ("le candidat", "le recruteur", "le propriétaire"), as in the legal pages.
- Translate the meaning, not the words, and keep it as short as the English: the layout is the
  same. A French text is on average a fifth longer; a button's must stay on one line at 390 px.
- Product names and technical terms people use in English stay: Portfolio (see above), PDF,
  Markdown, GitHub, RTT, CDI/CDD (French contract names were already French). Google Calendar is
  « Google Agenda » in French, the name Google gives it and the one the legal pages use.

## Adding a language

Add it to `LOCALES` and `LOCALE_NAMES` (`common/i18n.ts`): TypeScript then lists every message that
lacks it. The legal texts need a component per document, and `LanguageSwitch.svelte`, which links
to "the other" language, becomes a menu.
